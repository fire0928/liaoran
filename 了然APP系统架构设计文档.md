## 1. 项目概述与愿景

### 1.1 项目定位

**了然**是一款面向全年龄段用户的AI心理认知与自我疗愈应用，核心价值为"懂你、帮你、愈己"，提供从自我认知、情绪疏导到问题解决的全场景心理服务。

### 1.2 目标用户群体

| 用户群体 | 年龄范围 | 核心需求 |
|---------|---------|---------|
| 未成年人 | 12-17岁 | 学业压力、青春期心理、亲子关系 |
| 年轻人 | 18-35岁 | 职场压力、情感困惑、自我成长 |
| 中年职场人士 | 36-55岁 | 职场晋升、家庭关系、情绪管理 |
| 创业人群 | 25-45岁 | 创业压力、决策焦虑、团队管理 |
| 退休人群 | 55岁以上 | 孤独感、角色转变、老年心理保健 |

### 1.3 核心业务目标

- **短期(1-2年)**: 完成核心功能开发，积累100万+用户
- **中期(3-5年)**: 扩大至500万+用户，完善服务体系
- **长期(5年+)**: 成为国内领先的全年龄段心理服务平台

## 2. 架构设计原则

### 2.1 核心原则

```
┌─────────────────────────────────────────────────────────────────────┐
│                        架构设计七大原则                               │
├─────────────────────────────────────────────────────────────────────┤
│  1. 可扩展性 (Scalability)    - 水平扩展支持高并发                     │
│  2. 高可用性 (Availability)  - 多区域部署，故障自动恢复                │
│  3. 安全性 (Security)        - 端到端加密，符合隐私法规               │
│  4. 可维护性 (Maintainability)- 模块化设计，清晰边界                  │
│  5. 性能优先 (Performance)   - 毫秒级响应，优化用户体验               │
│  6. 领域驱动 (DDD)          - 围绕业务能力组织代码                    │
│  7. 渐进式演进 (Evolution)   - 支持功能迭代，避免过度设计             │
└─────────────────────────────────────────────────────────────────────┘
```

### 2.2 架构决策框架

| 维度 | 权衡因素 | 决策依据 |
|-----|---------|---------|
| 一致性 vs 可用性 | 数据实时性要求 | CP vs AP 选择 |
| 微服务 vs 单体 | 团队规模 vs 独立部署需求 | 团队<20人用模块化单体 |
| 自建 vs 托管 | 运维成本 vs 控制力 | AI服务优先托管 |
| SQL vs NoSQL | 事务需求 vs 扩展性 | 按数据特性选择 |

-- 用户表
CREATE TABLE users (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    phone VARCHAR(20) UNIQUE,
    email VARCHAR(255) UNIQUE,
    password_hash VARCHAR(255),
    status VARCHAR(20) DEFAULT 'active',  -- active, frozen, deleted
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    
    -- 第三方登录
    oauth_provider VARCHAR(50),
    oauth_id VARCHAR(255),
    
    -- 索引
    INDEX idx_phone (phone),
    INDEX idx_email (email),
    INDEX idx_oauth (oauth_provider, oauth_id)
);

-- 会员表
CREATE TABLE memberships (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    user_id UUID REFERENCES users(id),
    level INTEGER NOT NULL,  -- 0:free, 1:monthly, 2:quarterly, 3:yearly, 4:lifetime
    started_at TIMESTAMP NOT NULL,
    expired_at TIMESTAMP,
    auto_renew BOOLEAN DEFAULT false,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    
    UNIQUE INDEX idx_user_active (user_id, expired_at) WHERE expired_at > NOW()
);

-- 积分账户表
CREATE TABLE point_accounts (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    user_id UUID UNIQUE REFERENCES users(id),
    balance INTEGER DEFAULT 0,
    lifetime_earned INTEGER DEFAULT 0,
    lifetime_spent INTEGER DEFAULT 0,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    version INTEGER DEFAULT 0  -- 乐观锁
);

-- 用户画像表
CREATE TABLE user_portraits (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    user_id UUID UNIQUE REFERENCES users(id),
    
    -- 结构化画像数据 (JSON)
    demographic JSONB,
    psychological JSONB,
    needs JSONB,
    behavior JSONB,
    
    -- 向量表示 (用于RAG)
    embedding VECTOR(768),
    
    -- 状态快照
    current_mood VARCHAR(50),
    risk_level VARCHAR(20),
    last_interaction_at TIMESTAMP,
    
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    
    -- 搜索优化
    INDEX idx_portrait_embedding USING ivfflat (embedding vector_cosine_ops)
);

-- 对话会话表
CREATE TABLE chat_sessions (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    user_id UUID REFERENCES users(id),
    agent_type VARCHAR(50) NOT NULL,
    channel VARCHAR(20) DEFAULT 'text',
    status VARCHAR(20) DEFAULT 'active',
    started_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    ended_at TIMESTAMP,
    duration INTEGER,  -- 秒
    
    -- 摘要 (由AI生成)
    summary JSONB,
    
    INDEX idx_user_sessions (user_id, started_at DESC)
);

-- 对话消息表
CREATE TABLE chat_messages (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    session_id UUID REFERENCES chat_sessions(id),
    role VARCHAR(20) NOT NULL,  -- user, assistant, system
    
    -- 内容
    content JSONB NOT NULL,  -- {text, audio_url, images}
    
    -- AI元数据
    ai_meta JSONB,  -- {agent_type, model, tokens, latency}
    
    -- 用户反馈
    feedback JSONB,  -- {helpful, comment}
    
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    
    INDEX idx_session_messages (session_id, created_at)
);

-- 测评记录表
CREATE TABLE assessment_records (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    user_id UUID REFERENCES users(id),
    scale_id UUID NOT NULL,
    scale_version VARCHAR(20),
    
    -- 答题数据
    answers JSONB NOT NULL,  -- [{question_id, answer, score}]
    
    -- 原始分数
    raw_scores JSONB,
    
    -- 标准分数 (常模转换)
    standard_scores JSONB,
    
    -- AI增强解读
    ai_interpretation JSONB,
    
    -- 报告URL
    report_url VARCHAR(500),
    
    completed_at TIMESTAMP,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    
    INDEX idx_user_assessments (user_id, created_at DESC)
);

CREATE TABLE treehole_entries (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    user_id UUID REFERENCES users(id),
    
    -- 加密内容 (服务端加密)
    encrypted_content BYTEA,
    content_hash VARCHAR(64),  -- 用于去重验证
    
    -- 心情标签
    mood VARCHAR(50),
    mood_intensity INTEGER CHECK (mood_intensity BETWEEN 1 AND 10),
    
    -- 附件
    audio_url VARCHAR(500),
    images JSONB,
    
    -- 权限
    privacy VARCHAR(20) DEFAULT 'private',  -- private, ai_only
    allow_ai_analysis BOOLEAN DEFAULT false,
    
    -- AI分析结果 (加密)
    ai_analysis JSONB,
    
    -- 元数据
    location VARCHAR(200),
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    is_deleted BOOLEAN DEFAULT false,
    
    INDEX idx_user_entries (user_id, created_at DESC) WHERE NOT is_deleted
);

## 10. 架构决策记录 (ADR)

### ADR-001: 技术栈选择

**状态**: 已接受

**背景**: 需要为心理认知与自我疗愈APP选择合适的技术栈，要求支持三端(Android/iOS/HarmonyOS)、高并发、AI集成。

**决策**:
- 移动端: 原生开发 (Kotlin/Swift/ArkTS)
- 后端: Go (高性能服务) + TypeScript/NestJS (业务服务)
- AI服务: Python/FastAPI
- 数据库: PostgreSQL + Redis + Milvus

**后果**:
- 优点: 性能最优、团队技术储备足、AI集成方便
- 缺点: 三端需独立开发、维护成本较高

---

### ADR-002: 微服务 vs 模块化单体

**状态**: 已接受

**背景**: 初期团队规模约15-20人，需平衡开发效率与扩展性。

**决策**: 初期采用模块化单体架构，按领域拆分为松耦合模块。中期按需拆分为独立服务。

**后果**:
- 优点: 初期开发效率高、部署简单、团队学习成本低
- 缺点: 后期拆分有一定成本

---

### ADR-003: AI服务部署策略

**状态**: 已接受

**背景**: AI能力为核心竞争力，需平衡成本、隐私、效果。

**决策**: 
- 核心AI能力使用托管大模型API (OpenAI/Claude)
- 敏感数据处理使用私有部署小模型
- RAG知识库使用向量数据库

**后果**:
- 优点: 快速上线、效果有保障
- 缺点: API成本、隐私合规要求

---

### ADR-004: 树洞数据加密策略

**状态**: 已接受

**背景**: 树洞内容涉及用户高度隐私，需要端到端加密。

**决策**:
- 客户端使用设备密钥加密后上传
- 服务端仅存储密文，无法解密
- AI分析在客户端解密后本地处理，或使用联邦学习

**后果**:
- 优点: 极致隐私保护、符合法规
- 缺点: 功能受限(如服务端搜索)

---

### ADR-005: 测评系统设计

**状态**: 已接受

**背景**: 测评是核心功能，需支持灵活扩展多种量表。

**决策**:
- 量表元数据与题目分离存储
- 题目类型抽象化，支持选择题/量表题/开放题
- AI增强报告生成作为独立模块
- 支持版本管理和灰度发布

**后果**:
- 优点: 灵活扩展、快速上线新量表
- 缺点: 需要维护量表版本
